# Memo generation recovery

Institutional workspaces save each explicit generation request in the existing course Durable Object. Job identity includes the current account, course storage, source inputs, authoritative guidance configuration and selected model. Reloading retrieves the saved result using a fixed request token; editing source or changing course guidance requires a new explicit request. Existing maps and memos remain in their current storage.

Each attempt has a 90-second application budget and an 85-second Gateway budget. Only explicit retryable availability refusals permit automatic recovery, with backoff and at most three job attempts. Existing admitted model fallback rules still apply inside each attempt. Ambiguous provider timeouts and interrupted execution retain a terminal explanation and require deliberate retry because provider completion may be uncertain. Browser transport retries reuse the request identity. Every status or resume request rechecks account and course access.

Inputs and results expire after 24 hours; cleanup alarms physically remove them, allowing an active attempt up to 90 seconds to finish. Request-token metadata is retained for seven days to reject late replays. Unique attempt identifiers fence stale completion. Limits are 40 retained jobs per account, 1,000 request tokens and 20 explicit retry tokens per job. Credentials remain in the authenticated invocation, never the job record.

In the account workspace, **Submit memo** or **Update map** in Memo starts node generation; Continue does not. Continue checks only a successful submission for the current part, including a valid empty result. The two sources have independent last-successful baselines. An unchanged or non-narrative-only edit does not require a new paid call. The update request carries changed passages and stable current/original identities. A successful result commits graph changes and the new source baseline together in saved Undo; a failed, cancelled or stale request changes neither. Saved drafts and earlier relationships remain available. See [node submission](NODE_SUBMISSION_WORKFLOW_2026-11-04.md).

The older Meso review/connection generation paths remain compatibility behavior for the separate Node interface and retained APIs. They must not run on account Continue or introduce model-authored relationships. The cloud Gateway interface omits editable configuration fields that do not affect its request: base model reference, context limit, confidence threshold and relationship vocabulary. Stored configuration history and exports retain their compatible values.

Validation uses synthetic inputs and providers: client reload/lost-response recovery; job expiry, scope boundaries and stale completion; full four-level cumulative flow, independent memo update baselines and memo-only progression gating; actual local Worker authorization and Admission integration; desktop and phone browser progression with accessibility scans. Live model acceptance and the original failed Meso HTTP response require separate evidence.
