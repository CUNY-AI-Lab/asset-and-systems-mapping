# Generation recovery and Meso review

Institutional workspaces save each memo or connection-generation request in the existing course Durable Object. Job identity includes the current account, course storage, source inputs, authoritative guidance configuration and selected model. Reloading retrieves the saved result using a fixed request token; editing source or changing course guidance requires a new explicit request. Existing maps and memos remain in their current storage.

Each attempt has a 90-second application budget and an 85-second Gateway budget. Only explicit retryable availability refusals permit automatic recovery, with backoff and at most three job attempts. Existing admitted model fallback rules still apply inside each attempt. Ambiguous provider timeouts and interrupted execution retain a terminal explanation and require deliberate retry because provider completion may be uncertain. Browser transport retries reuse the request identity. Every status or resume request rechecks account and course access.

Inputs and results expire after 24 hours; cleanup alarms physically remove them, allowing an active attempt up to 90 seconds to finish. Request-token metadata is retained for seven days to reject late replays. Unique attempt identifiers fence stale completion. Limits are 40 retained jobs per account, 1,000 request tokens and 20 explicit retry tokens per job. Credentials remain in the authenticated invocation, never the job record.

Continue at a new mapping level generates guidance when that level has no current review or mapped elements. Existing Micro nodes carry into Meso; they no longer count as an already-generated Meso result. Advancing beyond Meso opens Review Micro and Meso, with Review the map and Continue to Exo-level actions. The cloud Gateway interface omits four editable configuration fields that do not affect its request: base model reference, context limit, confidence threshold and relationship vocabulary. Stored configuration history and exports retain their values.

Validation uses synthetic inputs and providers: client reload/lost-response recovery; job expiry, scope boundaries and stale completion; full four-level cumulative flow; actual local Worker authorization and Admission integration; desktop and phone browser progression with accessibility scans. Live model acceptance and the original failed Meso HTTP response require separate evidence.
