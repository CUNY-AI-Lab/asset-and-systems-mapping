# Two memos, four steps and three spheres — November 4, 2026

This is the current account-workspace contract, incorporating the user's later November 4 corrections. It supersedes the earlier two-sphere design, automatic relationship suggestions, required Field Notes and Map button. The companion [Memo workspace design](MEMO_WORKSPACE_2026-11-04.md) governs the latest canvas-first interface and marginal-update behavior. These are requirements for the current source; deployment and live acceptance require separate receipts. The separate Node application retains its older review workflow.

## Student progression

1. **Micro:** upload and submit the first memo. Add a small supported node set immediately. Students can edit nodes; they draw no relationships through the model.
2. **Meso:** students draw and name relationships between local nodes.
3. **Exo:** upload a separate second memo. Keep the original graph and classify new outside settings and broader conditions. Students connect Exo headings to selected local Meso relationships.
4. **Macro:** students connect cultural beliefs, historical patterns and economic structures to the settings or local relationships they affect. Named people and institutions are not Macro conditions.

The model returns at most six nodes per submission, with no guidance, relationships, examples, scopes or group memberships. Part 2 permits at most three Exo and three Macro nodes. Weak evidence may correctly produce no nodes. Source text is data, never authority to alter this contract. Successful processing is not certification of a student's interpretation.

Classification is relative to the focal participants and the pathway of effect. A community counselor working directly with focal students is local, not an Exo resource merely because the noun names a service. An outside counseling office may be Exo when the focal participants do not participate there directly. Organizational size, fame and proper-name status are not classification tests; uncertain evidence must not be converted into a confident placement. Students can correct a saved node's System and Type in the editor. Saving retains its ID, evidence, notes, position and existing relationships; a change that conflicts with a saved connection or membership is rejected without modifying the map.

Projects begins with a two-field creation form: **Project title** and **Creator name**. The creator can be a person or group and may be prefilled from the account profile; it never replaces the project title. A blank title becomes **Untitled systems map**. Saved rows show the existing title and creator, and search matches either. Opening a saved project preserves both. **Project → Project details** edits those same two fields for an existing map.

Every project opens onto its canvas. Memo, Notebook and Tools use one resizable sidebar with an underline for the active view; Hide collapses it while retaining all three controls. The new-project Memo upload receives a brief emphasis without stealing focus. Memo owns independent Part 1/Part 2 uploads, text and a sticky submit/Update map action; Notebook owns the four analytical steps, graph editing and optional Field Notes. There is no duplicate memo accordion, suggestion queue or Map button. The private-information checkbox and extra memo explanation are removed; existing sensitive memos without consent retain their permission control. Edited sources show “Memo changed | click Update map to submit”.

Continue, Back and selected-item actions stay above scrolling content. Continue requires only a successful memo-to-nodes submission for the current part, including a valid empty result; relationships and notes never gate it. It does not silently generate suggestions. Remove and Add to map reflect one saved state and never appear together for a node. Double-clicking a source starts a connection to an existing target or empty canvas. A new node and its named relationship save together; cancellation creates neither. Removing the source cancels the operation. Micro's instruction is “Select a node to edit it.” Evidence excerpts are labeled “Quote from memo.”

Back returns to visited workspace views without reverting map or memo edits; Continue advances the workflow. Undo and Redo restore saved edits separately and remain at the top of the sidebar. Their enabled state follows the current project, including after save/reload. Local view history resets when a different project opens. The item editor has no visible “Edit” caption, places the smaller On map status below the item name, and tints Connect from to match the selected node's system. Hide has no X. In evidence passages, matching item names are bolded without changing the quoted text.

## Independent sources and persistence

`submission` retains Part 1. `part2Submission` has its own text, filename, revision, fingerprint and privacy declarations. The second editor starts empty; it never displays or submits Part 1 as Part 2. The previous graph provides context. Changing a source does not clear prior nodes, relationships, positions, notes or retired-item decisions. Delayed imports and model results cannot replace a newer edit or a different project.

The account node-submission path uses `student-nodes-v1` and `preflightEvaluationPayload(project, true)`. The legacy Node review contract remains separate. Existing projects retain their graph, camera, analytical step and drafts; pending source edits are visible in Memo without replacing the canvas. A successful empty result remains complete after navigation and reload. The [node-submission contract](NODE_SUBMISSION_WORKFLOW_2026-11-04.md) specifies the optional incremental request and saved analysis baseline.

Each source optionally stores its last-successful `analysis` baseline. Draft saving never advances it. Meaningful narrative changes mark that part pending; whitespace-only and bibliography-only edits do not require paid regeneration. Changed passages and current/original node identities provide update context. A response can add new nodes or refresh eligible generated evidence through `existingId`, but cannot overwrite a student label, classification, color or evidence edit, revive a removed node, delete a record or alter a relationship. Broad rewrites and deletion-only changes may require the complete active memo as context. Graph changes and the new baseline commit atomically in saved Undo; stale, invalid, cancelled or failed results change neither.

A previously successful Part 1 baseline satisfies the initial Part 2 prerequisite even if Part 1 later has an unsubmitted edit. The active part’s pending edit still requires Update map before its own Continue, but it cannot lock an independently completed Part 2. Returning between memos preserves both drafts and never regenerates them automatically.

## Map and manual groups

Three content-fitted nested regions show **Microsystem**, **Exosystem** and **Macrosystem**; Meso relationships occupy Micro space. Node type and level colors are supplemented by labels and line patterns. Node color is Automatic or Blue, Teal, Purple, Amber, Rose or Slate. It never determines classification; optional `node.color` persists through saves, Undo and exports, and Automatic removes the override. Light/dark palette variants retain readable text while line patterns still identify systems. Relationship verbs remain attached to their routes. Auto-fit separates cards and shared route segments; unavoidable crossings have visual separation. Micro space grows with connection density and measured verb-label width: highly connected nodes sit centrally, while unconnected nodes occupy a separate pocket grouped by their existing colors. Saved manual pins remain fixed; Arrange map explicitly reorganizes them. Manual positions persist when auto-fit is off.

Region boundaries fit uneven content in both axes and enclose each inner contour and caption. This view calculation does not rewrite node coordinates. The account sidebar uses small semibold field labels and captions, readable content, compact secondary controls and one prominent content-width progression button. The compact account controls retain 44-pixel targets at desktop and phone sizes; 13–14px labels keep the action row readable at a 260px sidebar width. Focus states, dark-mode contrast and text wrapping remain part of the shared styling contract.

A manually created group records 1–24 exact live Meso `relationshipIds`. Its heading is an Exo or Macro node. The serialized target is a real member endpoint for compatibility; membership is defined by relationship IDs, not that anchor. Validation rejects unknown, retired, nested and out-of-scale members. Students must revise/remove a dependent group before removing its member relationship. Ordinary node-to-node links omit `relationshipIds`.

## Compatibility and verification

The optional schema-10 `editHistory` journal retains up to 30 edits, capped at 256 KiB with room for the serialized save envelope. It records editable data, not navigation or viewport state. Memo restoration advances source revisions and fingerprints; it never reruns the model. Preconditions reject an undo that conflicts with newer unrecorded work. Private backups preserve the journal and memo analysis baselines; every non-private export removes both. Earlier readers reject this new field, so a code rollback must retain the history-aware reader or use a forward fix. A database rollback or automatic stripping of user history is not authorized.

Schema 10 retains source texts, graph IDs, membership IDs, annotations and legacy scoped nodes. Analytical IDs and stored stage numbers remain unchanged. No Durable Object namespace or database restore is involved. Rollbacks must retain the schema-10 reader and both memo fields. Private JSON/Markdown retain both sources; CSV includes group IDs; PNG/PDF render the three regions and manual links. Audience restrictions continue to apply.

Tests must exercise the current node-only payload and zero model relationships at every step. Include independent uploads, meaningful and unchanged memo edits, stable identity after manual edits, preserved removals, empty and weak results, focal-participation classification, bibliography-only evidence, stale/failed jobs, atomic connected-node creation/cancel, manual groups, node colors, reload, exports, keyboard and phone behavior. Verify Continue only waits for the current part’s successful memo submission. Check the information flag’s exact copy, timer pause, dismissal and focus behavior. Controlled tests establish application behavior, not live model quality.

The four supplied PDFs remain outside Git. Approved live tests cover those real inputs and fabricated Bronx, Flushing and housing continuations. Real Gateway tests require approval of data and destination; fixture identity helpers are not production authentication. Record exact source, actual runtime/model, failures, retries and retained-state comparisons separately from CI and deployment receipts.

Policies/laws and external offices are represented at Exo under the explicit course convention. Macro names independently evidenced cultural, ideological, historical and economic conditions. See [classification evidence](CLASSIFICATION_EVIDENCE_2026-11-04.md). Existing saved maps are preserved; new classifications and explicit corrections use this convention.
